# Supporto per `default.xex` 0.0.0.11 – piano di implementazione

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Lo stesso sorgente si compila sia per la Collector's Edition USA 0.0.0.7 sia per quella
europea 0.0.0.11. CMake riconosce la versione dallo xex in `game/` e sceglie indirizzi e
`functions.toml` di quella versione.

**Architecture:** In configurazione CMake legge l'identità dello xex con uno script Python e la
confronta con una tabella di edizioni note (`nfsc/cmake/editions.cmake`). Poi genera un header
`nfsc_edition.h` e copia il `functions.toml` della versione in un percorso non tracciato, che il
manifest include. Gli hook usano nomi simbolici da `addresses_v7.h` / `addresses_v11.h`. Ogni
gruppo di hook ha un flag di funzione (`NFSC_FEATURE_*`), così una funzione non ancora mappata
sulla v11 si compila senza.

**Tech Stack:** C++23 (clang), CMake ≥ 3.25 / Ninja Multi-Config, ReXGlue SDK 0.11.0,
Python 3.12 (unittest, solo libreria standard).

**Spec:** `docs/superpowers/specs/2026-11-21-xex-0.0.0.11-support-design.md`

## Global Constraints

- v7: title `454107EC`, versione `0x00000007`, digest `974B32299EF1C58DF946DADAA0CD033A972F9148`, nome "Collector's Edition (USA) 0.0.0.7".
- v11: title `454107EC`, versione `0x0000000B`, digest `8BCC2F4CDF7888F85EE82C012ED14D570F6E0231`, nome "Collector's Edition (Europe) 0.0.0.11".
- La build v7 deve espandersi esattamente negli stessi simboli `sub_*` / `__imp__sub_*` di oggi e usare un `functions.toml` identico byte per byte a quello attuale.
- Mai compilare codice generato da una versione con gli indirizzi di un'altra: se lo xex c'è e non corrisponde alla versione scelta, `FATAL_ERROR`.
- Dopo configurazione e build `git status` è pulito: nessun file tracciato viene modificato da CMake.
- Nel repository non finiscono codice generato, byte dello xex, `image.bin` o asset (`game/`, `nfsc/generated/default/`, dump sono già o vanno messi in `.gitignore`).
- Codice e commenti in inglese, come il resto del progetto; `docs/DEVELOPMENT.nl.md` in olandese.
- Una funzione che sulla v11 risulta molto più difficile resta disattivata solo per la v11 (flag a 0); la limitazione va scritta in README e ROADMAP.md.
- Le prove di gioco interattive le fa l'utente; chi implementa arriva da solo fino al "menu principale senza errori nel log".

## Review Focus

1. **Cambio di gioco in una build esistente:** se si sostituisce `game/default.xex` con un'altra versione, la configurazione riparte e sceglie l'altra versione, e il codegen riparte. Nessun codice generato vecchio resta mescolato al nuovo. → Task 2, step 6.
2. **`game_path.txt` che punta ai dati dell'altra versione:** il messaggio all'avvio nomina tutte e due le edizioni e dice di ricompilare, invece di andare in crash. → Task 7, step 2.
3. **Widescreen disattivato sulla v11 con `aspect_ratio = auto` su un monitor ultrawide:** niente immagine stirata e niente cambio di `ui.video_mode_width`; il gioco resta a 16:9. → Task 3, step 5.
4. **Manca `game/default.xex` ma c'è la ISO:** l'errore di configurazione dice il comando esatto `python tools/xdvdfs.py extract <iso> game default.xex`. → Task 2, step 5.
5. **Python non trovato, o trovato quello sbagliato:** `find_package(Python3 3.10 COMPONENTS Interpreter REQUIRED)` dà un errore chiaro; lo script non usa moduli esterni. → Task 1, step 4 e Task 2, step 3.
